## 1. 执行原则

- 先跑通闭环，再优化体验，最后扩展短剧高级编辑能力。
- 每次开发遵循 [CLAUDE.md](../../CLAUDE.md) 的变更四步法：确认边界、调整文档、修改代码、同步测试。
- 每个阶段完成后立即更新本计划 checkbox 和相关文档。
- 每个提交保持原子化，完成后立即 push 到 `origin`。

## 15. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 供应商 API 格式差异大 | Provider 抽象层 + JSON config + adapter 单测。 |
| 视频任务耗时长 | 统一异步任务模型 + Redis 状态 + 前端轮询。 |
| API 成本不可控 | 生成前 estimate + 配额扣减 + 管理员可调成本。 |
| 模型太多导致用户困惑 | 默认自动路由，模型选择放高级设置。 |
| 短剧功能范围过大 | P8 只做 MVP，高级时间线放 P10。 |
| 文档与代码不同步 | 每阶段完成立即更新本计划 checkbox 和相关 spec。 |
